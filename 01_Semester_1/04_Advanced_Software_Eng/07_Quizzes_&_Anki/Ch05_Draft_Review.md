## What Is Software Design? — ما تصميم البرمجيات؟

### q1 · ch5_design_bridge
**Bloom:** Understand
**Question:** What does software design turn into a technical blueprint?
**السؤال:** إلى ماذا يحوّل تصميم البرمجيات المتطلبات؟

- **A.** ✓ The approved requirements become a technical blueprint  
  تحويل المتطلبات المعتمدة إلى مخطط تقني قابل للبناء
- **B.** Executable code carries out the required system behavior  
  شيفرة تنفيذية تحقق السلوك المطلوب للمستخدم النهائي
- **C.** Verification evidence records the system's test outcomes  
  تقرير تحقق يوثق نتائج اختبار وظائف النظام
- **D.** A released interface lets users access the completed product  
  واجهة منشورة تتيح استخدام المنتج بعد اكتماله

**Key:** A — The approved requirements become a technical blueprint
**المفتاح:** A — تحويل المتطلبات المعتمدة إلى مخطط تقني قابل للبناء
**Why:** Design translates the requirements into a blueprint that guides construction.
**التوضيح:** يحوّل التصميم المتطلبات إلى مخطط يوجّه بناء البرمجيات.

## Conceptual and Technical Design — التصميم المفهومي والتصميم الفني

### q1 · ch5_conceptual_what
**Bloom:** Understand
**Question:** What does conceptual design emphasize?
**السؤال:** على ماذا يركز التصميم المفهومي؟

- **A.** ✓ The capabilities that users can observe and request  
  القدرات التي يستطيع المستخدمون رؤيتها وطلبها
- **B.** The internal hierarchy of calling software components  
  التسلسل الداخلي لاستدعاء مكونات البرمجيات
- **C.** The algorithms that programmers select for execution  
  الخوارزميات التي يختار المبرمجون تنفيذها
- **D.** The memory layout used by components at runtime  
  تنظيم الذاكرة الذي تستخدمه المكونات أثناء التشغيل

**Key:** A — The capabilities that users can observe and request
**المفتاح:** A — القدرات التي يستطيع المستخدمون رؤيتها وطلبها
**Why:** Conceptual design explains what the system offers from an external user perspective.
**التوضيح:** يشرح التصميم المفهومي ما يقدمه النظام من منظور المستخدم الخارجي.

**Key:** B — How the architecture realizes required system behavior

**التوضيح:** يصف التصميم الفني كيفية تنفيذ النظام لقدراته المطلوبة.

## Objectives of Software Design — أهداف التصميم البرمجي

### q1 · ch5_design_objectives_set
**Bloom:** Understand
**Question:** Which set states the software design objectives?
**السؤال:** أي مجموعة تمثل أهداف التصميم كما وردت في الكتاب؟

- **A.** ✓ Correct, complete, understandable, right-level, maintainable  
  صحيح وكامل ومفهوم وبالمستوى المناسب وقابل للصيانة
- **B.** Fast, portable, compact, secure, reusable across projects  
  سريع ومحمول ومختصر وآمن وقابل لإعادة الاستخدام
- **C.** Low-cost, familiar, automated, distributed, fault-resistant  
  منخفض الكلفة ومألوف ومؤتمت وموزع ومقاوم للأعطال
- **D.** Compact, generic, current, independent, measurable, flexible  
  مدمج وعام وحديث ومستقل وقابل للقياس والتوسع

**Key:** A — Correct, complete, understandable, right-level, maintainable
**المفتاح:** A — صحيح وكامل ومفهوم وبالمستوى المناسب وقابل للصيانة
**Why:** The stated objectives are correctness and completeness, understandability, suitable level, and maintainability.
**التوضيح:** أهداف التصميم هي الصحة والاكتمال وقابلية الفهم والمستوى المناسب وقابلية الصيانة.

### q2 · ch5_objective_correct_complete
**Bloom:** Understand
**Question:** What does a correct and complete design preserve?
**السؤال:** ماذا يحافظ عليه التصميم الصحيح والكامل؟

- **A.** Implementation details unrelated to stated system needs  
  تفاصيل تنفيذ لا ترتبط بالحاجات المحددة
- **B.** ✓ Required behavior and relevant system requirements  
  السلوك المطلوب والمتطلبات المرتبطة بالنظام
- **C.** Every imaginable feature requested by future users  
  كل ميزة قد يطلبها المستخدم مستقبلاً للنظام
- **D.** Only visible screens approved by the marketing team  
  الشاشات الظاهرة التي اعتمدها فريق التسويق

**Key:** B — Required behavior and relevant system requirements
**المفتاح:** B — السلوك المطلوب والمتطلبات المرتبطة بالنظام
**Why:** Correctness and completeness require the design to represent the specified needs without omissions.
**التوضيح:** تتطلب الصحة والاكتمال أن يمثل التصميم الحاجات المحددة من دون إغفال.

### q3 · ch5_objective_understandable
**Bloom:** Understand
**Question:** A design is understandable when its structure is...
**السؤال:** يكون التصميم قابلاً للفهم عندما تكون بنيته...

- **A.** Expanded with every low-level coding statement  
  موسع بكل تعليمة برمجية منخفضة المستوى
- **B.** Written only in vendor-specific machine terms  
  مكتوب بمصطلحات آلة خاصة بمورد واحد
- **C.** ✓ Clear enough for its intended technical readers  
  واضح بما يكفي للقراء الفنيين المقصودين
- **D.** Hidden from everyone except its original author  
  مخفي عن الجميع عدا مؤلفه الأصلي

**Key:** C — Clear enough for its intended technical readers
**المفتاح:** C — واضح بما يكفي للقراء الفنيين المقصودين
**Why:** Understandability depends on clear organization at the intended level of detail.
**التوضيح:** تعتمد قابلية الفهم على وضوح التنظيم وبالمستوى المقصود من التفاصيل.

### q4 · ch5_objective_right_level
**Bloom:** Understand
**Question:** What does “at the right level” mean for a design?
**السؤال:** ماذا يعني أن يكون التصميم بالمستوى المناسب؟

- **A.** It contains every implementation statement in full  
  يتضمن كل تعليمة تنفيذية بصورة كاملة
- **B.** It omits all structure until coding is finished  
  يحذف البنية حتى انتهاء كتابة الشيفرة
- **C.** It gives every stakeholder an identical detail level  
  يعرض المستوى نفسه من التفاصيل للجميع
- **D.** ✓ Its detail matches the decision and intended audience  
  تفاصيله تلائم القرار والجمهور المقصود

**Key:** D — Its detail matches the decision and intended audience
