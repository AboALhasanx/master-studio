2. ILF & EIF Mathematical Weighting

Albrecht's standard complexity weights reflecting architectural storage overhead

ILF · Internal Logical Files Internal Data
  • 🔒 Control: Created, updated, and deleted by internal transactions.
  • 🎯 Intent: Hold data required to satisfy internal business rules.
  • ⚡ Albrecht Complexity Multipliers:
Low 7
Average 10
High 15
EIF · External Interface Files External Data
  • 🌐 Control: Read-only reference; never mutated by our system.
  • 🎯 Intent: Avoid data duplication while leveraging foreign records.
  • ⚡ Albrecht Complexity Multipliers:
Low 5
Average 7
High 10
💡
Why ILF Weights are Higher than EIF (10 vs 7 Average)
ILFs require full schema management, transaction acid rollback, and persistence overhead. EIFs only consume read-parsing logic.
تتطلب ملفات ILF إدارة كاملة للبيانات والتخزين والتحديث، بينما تقتصر EIF على قراءة البيانات فقط.

3. The Golden Duality Rule of FPA

An External Interface File in System A MUST be an Internal Logical File in System B

Application System A (E-Commerce)

Consumer

Queries shipping rates and package tracking status.

Counted as: EIF (Weight: 7)

System A only reads rates; does not update them.

⇄ Shared Entity

Logistics Carrier B (FedEx/DHL)

Maintainer

Creates waybills, scans barcodes, and updates courier routes.

Counted as: ILF (Weight: 10)

System B fully creates, maintains, and stores the tracking DB.

⚠️
Classic Exam Trap: Counting a File Twice in the Same System
Never count a single file group as both an ILF and an EIF within the same application boundary! A file is strictly ILF if maintained internally, or EIF if referenced externally.
تحذير امتحاني: لا تحسب الملف الواحد كـ ILF و EIF معاً داخل نفس النظام! إما أن يُدار داخلياً أو يُقرأ خارجياً.
Data Function Types classify all logical files maintained or referenced by the software application.
تصنف دوال البيانات كافة الملفات المنطقية المخزنة أو المشار إليها داخل النظام البرمجي.
