2. Mathematical Formulation of Unadjusted Function Points

The rigorous double-summation model: Decoupling functional volume from implementation complexity

UFP Unadjusted FP = ∑i=15 5 Components ∑j=13 3 Complexities [ Wij Weight Matrix × Zij Count (SRS) ]
Index i ∈ {1 .. 5} Component
Iterates over the 5 functional types: 1=EI, 2=EO, 3=EQ, 4=ILF, 5=EIF.
المؤشر i: يعبر عن الأنواع الوظيفية الخمسة.
Index j ∈ {1 .. 3} Complexity
Iterates over the 3 complexity levels: 1=Low, 2=Average, 3=High.
المؤشر j: يمثل مستويات التعقيد الثلاثة (منخفض، متوسط، مرتفع).
Wij ∈ Matrix Constant
The standard Albrecht empirical weight assigned to component i at level j.
W: الوزن المعياري المأخوذ من جدول الأوزان الثابت.
Zij ∈ Count Variable
Number of functional elements identified from user requirements specification.
Z: عدد العناصر والوظائف المستخرجة من وثيقة المتطلبات (SRS).
💡
Key Principle: Sizing Independent of Programming Language
Unadjusted Function Points (UFP) measure purely the user-identifiable functional size. Whether implemented in C++, Java, or Python, the UFP of an SRS remains identical!
المبدأ الأساسي: نقاط الوظيفة غير المعدلة (UFP) تقيس الحجم المنطقي للمتطلبات فقط، وتظل ثابتة تماماً مهما تغيرت لغة البرمجة!
