### Q8.1. Software testing is:
(a) the process of demonstrating that errors are not present · (b) the process of establishing confidence that a program does what it is supposed to do · (c) the process of executing a program to show it is working as per specifications · (d) the process of executing a program with the intent of finding errors
{: .keep-next }
> **(d) the process of executing a program with the intent of finding errors**
>
> **Software testing is defined classically by Myers (1979) as the process of executing a program with the intent of finding errors.** Testing demonstrates the presence of defects rather than their absolute absence.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.1.1 (p. 365); slide 3; question on slide 189.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> تعريف مايرز الكلاسيكي (Glenford Myers, 1979): الاختبار هو عملية تنفيذ البرنامج بقصد اكتشاف الأخطاء والعيوب الكامنة، وليس إثبات خلوه التام من الأخطاء لأن الاختبار الشامل مستحيل حسابياً.

### Q8.2. Software mistakes during coding are known as:
(a) failures · (b) defects · (c) bugs · (d) errors
{: .keep-next }
> **(c) bugs**
>
> **When developers make mistakes while coding, these mistakes are called bugs.** People make errors (a good synonym is mistake); a failure occurs only when a fault executes.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.2.1 (p. 369); slide 9; question on slide 189.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> الخطأ البشري أثناء كتابة الكود يسمى «bug». لا تخلط بين الخيارين: errors هو الفعل البشري العام، أما bugs فهو الاسم الذي يطلقه المصدر على أخطاء الترميز.

### Q8.3. Functional testing is known as:
(a) Structural testing · (b) Behavior testing · (c) Regression testing · (d) None of the above
{: .keep-next }
> **(b) Behavior testing**
>
> **Functional testing is known as behavioral testing or black-box testing.** It treats the software component as a black box, deriving test inputs purely from requirements specifications without examining internal structural control flow.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3 (p. 371); slide 13; question on slide 189.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> الفحص الوظيفي (Functional Testing) يُعرف أيضاً بالفحص السلوكي (Behavioral Testing) أو فحص الصندوق الأسود (Black-box)؛ حيث تُبنى حالات الاختبار استناداً إلى المدخلات والمخرجات المطلوبة بالمواصفات دون النظر للكود الداخلي.

### Q8.4. For a function of n variables, boundary value analysis yields:
(a) 4n+3 test cases · (b) 4n+1 test cases · (c) n+4 test cases · (d) None of the above
{: .keep-next }
> **(b) 4n+1 test cases**
>
> **For a function of $n$ variables, boundary value analysis (BVA) yields $4n + 1$ test cases.** Under the single-fault assumption, each variable is tested at four boundary extremes ($min, min+, max-, max$) while holding other variables at nominal, plus one common baseline test case with all variables at nominal values: $4(n) + 1 = 4n + 1$.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.1 (p. 372); slides 15, 20; question on slide 189.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> تحليل القيم الحدية القياسي (BVA) يولد $4n+1$ حالة اختبار لعدد $n$ من المتغيرات اعتماداً على فرضية العيب المنفرد (Single-fault assumption)، حيث يُختبر كل متغير عند 4 قيم حدية وتبقى بقية المتغيرات عند قيمتها الطبيعية (Nominal)، بالإضافة لحالة اختبار مركزية واحدة.

### Q8.5. For a function of two variables, how many cases will be generated by robustness testing?
(a) 9 · (b) 13 · (c) 25 · (d) 42
{: .keep-next }
> **(b) 13**
>
> **For a function of two variables ($n = 2$), robustness testing generates $6n + 1 = 6(2) + 1 = 13$ test cases.** Robustness testing adds values just outside the valid boundaries ($min-$ and $max+$), testing 6 extreme points per variable plus the nominal center.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.1 (p. 372); slides 24–25; question on slide 190.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> فحص المتانة (Robustness Testing) يختبر القيم الواقعة خارج الحدود مباشرة ($min-$ و $max+$) بالإضافة للحدود الأربعة، فيكون لكل متغير 6 قيم حدية بالإضافة للحالة الطبيعية ($6n+1$). لمتغيرين اثنين: $6(2)+1 = 13$ حالة اختبار.

</div>

### Q8.6. For a function of n variables robustness testing of boundary value analysis yields:
(a) 4n+1 · (b) 4n+3 · (c) 6n+1 · (d) None of the above
{: .keep-next }
> **(c) 6n+1**
>
> **For a function of $n$ variables, robustness testing of boundary value analysis yields $6n + 1$ test cases.** Each variable takes values $\{min-, min, min+, nom, max-, max, max+\}$, producing $6$ tests per variable held against nominal values of all other inputs, plus $1$ all-nominal test case.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.1 (p. 372); slide 24; question on slide 190.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> قاعدة عدد حالات اختبار المتانة العامة لـ $n$ متغير هي $6n+1$، وهي امتداد لقاعدة BVA القياسية ($4n+1$) بإضافة نقطتين غير صالحتين لكل متغير لاختبار مناعة النظام ضد المدخلات غير المقبولة.

</div>

### Q8.8. A node with indegree=0 and out degree ≠0 is called
(a) Source node · (b) Destination node · (c) Transfer node · (d) None of the above
{: .keep-next }
> **(a) Source node**
>
> **In a control flow graph, a node with indegree $= 0$ and outdegree $\ne 0$ is called a source node.** It represents the entry point of the program or module.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.4 (p. 406); flow-graph background, slide 105; question on slide 190.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> في مخطط تدفق التحكم (Control Flow Graph)، العقدة التي لا يدخل إليها أي سهم ($indegree=0$) ويخرج منها مسار واحد أو أكثر ($outdegree \ne 0$) تُسمى عقدة المصدر أو البداية (Source Node).

</div>

### Q8.9. A node with indegree ≠0 and out degree=0 is called
(a) Source node · (b) Predicate node · (c) Destination node · (d) None of the above
{: .keep-next }
> **(c) Destination node**
>
> **In a control flow graph, a node with indegree $\ne 0$ and outdegree $= 0$ is called a destination node (or sink node).** It represents the exit point or termination of the control flow.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.4 (p. 406); flow-graph background, slide 105; question on slide 190.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> العقدة التي تدخل إليها مسارات ($indegree \ne 0$) ولا يخرج منها أي مسار ($outdegree=0$) هي عقدة المقصد أو النهاية (Destination / Sink Node).

</div>

### Q8.10. A decision table has
(a) Four portions · (b) Three portions · (c) Five portions · (d) Two portions
{: .keep-next }
> **(a) Four portions**
>
> **A decision table has four distinct portions:** (1) Condition Stub in the upper left, (2) Condition Entry in the upper right, (3) Action Stub in the lower left, and (4) Action Entry in the lower right.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.3 (p. 395); slide 77; question on slide 191.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> جدول القرار (Decision Table) يتكون بنيوياً من 4 أرباع محددة: جذع الشروط (أعلى اليسار)، بنود الشروط (أعلى اليمين)، جذع الإجراءات (أسفل اليسار)، وبنود الإجراءات (أسفل اليمين).

### Q8.12. Equivalence class partitioning is related to
(a) Structural testing · (b) Blackbox testing · (c) Mutation testing · (d) All of the above
{: .keep-next }
> **(b) Blackbox testing**
>
> **Equivalence class partitioning is a black-box (functional) technique:** the input domain is divided into classes from the specification, and test cases are chosen from each class without looking at the code.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.2 (p. 390); slides 61–62; question on slide 191.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**

### Q8.13. Cause effect graphing techniques is one form of
(a) Maintenance testing · (b) Structural testing · (c) Function testing · (d) Regression testing
{: .keep-next }
> **(c) Function testing**
>
> **Cause-effect graphing is one form of functional (black-box) testing technique.** It translates complex natural-language specifications into Boolean logical graphs relating input conditions (causes) to output responses (effects) to systematically generate decision tables.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3.4 (p. 402); slide 92; question on slide 191.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
> مخطط السبب والنتيجة (Cause-Effect Graphing) هو تقنية متقدمة تابعة لفحوصات الصندوق الأسود الوظيفية (Functional Testing)، تهدف لتحويل العلاقات المنطقية بين المدخلات والمخرجات إلى جداول قرار دقيقة.

### Q8.25. Which is not a functional testing technique?
(a) Boundary value analysis · (b) Decision table · (c) Regression testing · (d) None of the above
{: .keep-next }

>
> **Regression testing is not a functional testing technique.** Boundary value analysis and decision tables are functional (black-box) techniques; regression testing is re-testing after changes.
>
> *Source: Aggarwal & Singh (3rd ed.), question printed pp. 451–455, publisher key p. 499; §8.3 (p. 371); slide 13; question on slide 194.*

> [!NOTE]
> **ملاحظة الطالب والفخ الامتحاني:**
>
