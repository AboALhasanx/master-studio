# البحث — من BFS إلى A*

> **من وين جاي:** W01 عرّفت الـ**agent** (PEAS + بيئة). هذا الفصل يجاوب: الـagent كيف **يختار** سلسلة أفعال توصل لهدف؟ الجواب آلة واحدة اسمها **search**، وكل الخوارزميات في هذا الفصل هي نفس الآلة بتبديل سطر واحد.

---

## 1. صياغة المسألة — الخمسة التي لا تُنسى (ص 2)

قبل أي بحث، لازم تصوغ المسألة بخمسة عناصر. هذه أول علامة في أي سؤال «formulate»:

| # | العنصر | السؤال الذي يجيبه |
| :--: | :--- | :--- |
| 1 | **State** | كيف نصف حالة العالم؟ (كل ما يهمّ للمسألة) |
| 2 | **Initial state** | من وين نبدأ؟ |
| 3 | **Goal test** | كيف نعرف إن وصلنا؟ (شرط، مو حالة واحدة) |
| 4 | **Actions / Operators** | شنو الانتقالات المسموحة؟ |
| 5 | **Path cost** | شكد كلّف المسار؟ (غالباً 1 لكل حركة) |

$$g(n) = \text{كلفة المسار من البداية إلى } n \qquad h(n) = \text{تقدير الكلفة من } n \text{ إلى الهدف}$$

**⚠️ مصيدة:** **Goal test** مو **Goal state**. الأولى **شرط** (مثلاً «$y = 2$»)، والثانية **حالة محددة**. في مسألة الجرار، الهدف $(2,n)$ هو **عائلة حالات** — أي $n$. لهذا نكتب **test** لا **state**.

### مثال مُصاغ كاملاً — الجراران (Water Jug)

| العنصر | الصياغة |
| :--- | :--- |
| State | $(x,y)$ حيث $x$ ماء الجرار الأول و$y$ الثاني |
| Initial | $(0,0)$ |
| Goal test | $x = 2$ (أي $(2,n)$ لأي $n$) |
| Actions | املأ $x$ · املأ $y$ · فرّغ $x$ · فرّغ $y$ · صبّ $x \to y$ · صبّ $y \to x$ |
| Path cost | 1 لكل عملية |

**لاحظ:** كل عملية تُنتج **حالة جديدة**، والحالات كلها تُرتَّب في **شجرة** — لا في قائمة عشوائية.

## 2. الشجرة و Open/Closed (ص 5–6)

| المفهوم | المعنى |
| :--- | :--- |
| **State** | عقدة في الشجرة |
| **Action** | حافة (edge) |
| **Initial state** | الجذر (root) |
| **Solution** | مسار من الجذر إلى عقدة هدف |

**القائمة المفتوحة (OPEN):** الحالات التي **وُلِّدت ولم تُوسَّع** بعد.
**القائمة المغلقة (CLOSED):** الحالات التي **وُسِّعت** فعلاً (تم فحص أبنائها).

### القالب الموحّد — هذا هو المحرّك (ص 6)

$$ \textbf{OPEN} \leftarrow \{\text{initial}\} $$
$$ \textbf{while } OPEN \neq \varnothing: $$
$$ \quad n \leftarrow \text{First}(OPEN); \quad \text{Pop}(OPEN) $$
$$ \quad \textbf{if } \text{Goal}(n): \ \textbf{return} \ \text{success} $$
$$ \quad \textbf{else}: \quad OPEN \leftarrow \text{QueueFunction}\big(OPEN,\ \text{Expand}(n)\big) $$
$$ \textbf{return} \ \text{failure} $$

**اقرأ القالب مرتين:** اختبار الهدف يصير **عند الإخراج (expansion)** مو عند التوليد. وهذا قرار يغيّر التتبّع كله — فالطالب الذي يفحص الهدف عند التوليد يحصل على أرقام مختلفة.

## 3. الفكرة المركزية: كل الخوارزميات مختلفة في سطر واحد

$$\boxed{\text{كل خوارزميات البحث تتشابه إلا في } \textbf{QueueFunction}}$$

هذه الجملة هي **عمود الفصل**. لو حفظتها، حفظت نصف الدرجة: كل ما تسأل عنه «شنو الفرق بين BFS وUCS؟» جوابه: **ترتيب OPEN**.

| الخوارزمية | QueueFunction | الترتيب |
| :--- | :--- | :--- |
| **BFS** | FIFO (طابور) | الأقدم أولاً |
| **DFS** | LIFO (مكدّس) | الأحدث أولاً |
| **UCS** | رتّب بالـ $g(n)$ | الأرخص أولاً |
| **Greedy / Best-First** | رتّب بالـ $h(n)$ | الأقرب للهدف أولاً |
| **A\** | رتّب بالـ $f(n) = g(n)+h(n)$ | الأرخص **مع** التقدير |

**🧠 مرساة:** BFS وDFS يفرق بينهما **سطر واحد فقط**. لا تحفظهما كخوارزميتين منفصلتين — احفظهما كـ**ترتيبين** لنفس القالب.

## 4. البحث غير المُعلَم (Uninformed)

سمّي «غير معلَم» لأنه **لا يعرف** شيئاً عن قرب الهدف. يجرّب بلا توجيه.

### 4.1 BFS — عرض أولاً

**الفكرة:** يوسّع كل مستوى قبل ما ينزل للمستوى التالي.

**التحليل** (هدف عند العمق $d$، عامل تفرّع $b$):

$$\text{Time} = 1 + b + b^2 + \cdots + b^d + (b^{d+1}-b) = O(b^{d+1})$$
$$\text{Space} = O(b^{d+1})$$

| الخصيصة | القيمة |
| :--- | :--- |
| Complete؟ | ✅ نعم |
| Optimal؟ | ❌ **لا** — يجد **أقل عدد حركات**، مو **أقل كلفة** |
| الذاكرة | **الكارثة** — $O(b^{d+1})$ |

**الأرقام التي تُخيف:** عند $b=10$ و10,000 عقدة/ثانية و1,000 بايت/عقدة ← الذاكرة وحدها تحتاج

$$10^{11} \times 10^{3}\ \text{بايت} = 10^{14}\ \text{بايت} \approx 100\ \text{تيرابايت}$$

لهذا الذاكرة هي القيد الحقيقي، لا الوقت: حساب $10^{11}$ عقدة يأخذ ساعات، لكن حفظها يحتاج مزرعة أقراص.

### 4.2 DFS — عمق أولاً

**الفكرة:** يوسّع أعمق عقدة أولاً.

$$\text{Time} = O(b^m) \qquad \text{Space} = O(bm)$$

حيث $m$ أقصى عمق. **الذاكرة خطّية** — وهذا كل ما يميّزه.

| الخصيصة | القيمة |
| :--- | :--- |
| Complete؟ | ❌ **لا** — قد يدخل فرعاً لا نهائياً |
| Optimal؟ | ❌ لا |
| الذاكرة | ✅ $O(bm)$ — أفضل بكثير من BFS |

**تجنّب الحالات المتكررة:** لا ترجع للأب أو الجدّ (في الثمانية لا تحرّك لأعلى بعد أن حرّكت لأسفل)، ولا تُنشئ مسارات فيها دورات.

### 4.3 UCS — البحث بالكلفة الموحّدة (Branch & Bound)

$$\text{QueueFunction} = \text{sort by } g(n)$$

$$g(n) = \sum \text{كلفة العمليات على طول المسار من الجذر إلى } n$$

| الخصيصة | القيمة |
| :--- | :--- |
| Complete؟ | ✅ نعم |
| Optimal؟ | ✅ **نعم** — أول هدف يُخرَج هو الأرخص |
| الزمن/الذاكرة | أُسّيان — قد يستكشف شجرة فرعية رخيصة كبيرة قبل مسار غالٍ قصير |

**⚠️ مصيدة:** UCS **لا** ينظر للهدف إطلاقاً — كل عمله في $g$. ولهذا يضمن الأمثَليّة، لكنه يزحف ببطء.

### 4.4 IDS — التعميق التكراري

**الفكرة:** DFS بحدّ عمق يزيد تدريجياً ($0, 1, 2, \ldots$).

$$\text{Time} = O(b^d) \qquad \text{Space} = O(bd)$$

**السؤال الذي يجاوبه:** «مو DFS يدخل فرعاً لا نهائياً؟» — الحدّ يمنعه. «ومو BFS يستهلك ذاكرة؟» — IDS يستعمل ذاكرة DFS.

| الخصيصة | القيمة |
| :--- | :--- |
| Complete؟ | ✅ نعم |
| Optimal؟ | ❌ لا (إلا إذا كل الكلف متساوية) |
| الذاكرة | ✅ $O(bd)$ |

**الاعتراض الشائع:** «ما يكرّر العمل؟» — نعم، لكن التكرار **رخيص**: المستويات العليا تُزار أكثر، وهي الأقل كلفة. المجموع يبقى ضمن ثابت من $b^d$.

### 4.5 Bidirectional Search

بحثان: من البداية للأمام ومن الهدف للخلف، ويتقابلان في الوسط.

$$\text{Time \& Space} = O(b^{d/2})$$

طيّ الـ$d$ إلى نصفين يقلّل الحجم من **مربّع** إلى **جذر**. لكن له تعقيدات: أي حالة هدف نختار؟ متى نعرف إن البحثين تقاطعا؟ أي خوارزمية لكل اتجاه؟

## 5. البحث المُعلَم (Informed)

«مُعلَم» لأنه يستعمل **$h(n)$** — تقدير ذكي يوجّه البحث.

### 5.1 Best-First — الاسم العام

$$\text{QueueFunction} = \text{sort by } h(n) \text{ only}$$

مثال $h$ للثمانية: **Manhattan distance** (مجموع مسافات القطع الأفقية والعمودية).

**التحذير:** «best-first isn't necessarily best» — جودة البحث = جودة $h$ حرفياً.

### 5.2 Hill Climbing (Greedy Search)

نسخة جشعة: يختار الابن الأفضل فقط، ولا يرجع للخلف.

| المشكلة | المعنى |
| :--- | :--- |
| **Local maxima** | قمة محلية أعلى من جيرانها وليست القمة العامة |
| **Ridges** | حافة ضيقة عالية — كل خطوة قريبة تهبط |
| **Plateaus** | هضبة مستوية — لا تدرّج يوجّه الحركة |
| **Foothill** | نفس فكرة القمة المحلية بنائجة مختلفة |

**الحلول:** **random walk** (خطوة عشوائية عند التعادل) · إعادة التشغيل من نقاط مختلفة · خطوتان بدل واحدة (look ahead).

**⚠️ مصيدة:** Hill climbing **ليس** نسخة من A*. هو **greedy**: يستعمل $h$ **فقط** ولا يحفظ $g$. ولهذا لا يضمن الأمثلية أبداً.

### 5.3 A\* — الحل الكامل

$$f(n) = g(n) + h(n)$$

- $g(n)$ = الكلفة **المدفوعة** فعلاً من الجذر.
- $h(n)$ = الكلفة **المقدَّرة** إلى الهدف.
- $f(n)$ = أفضل تقدير لكلفة المسار الكامل عبر $n$.

| الخصيصة | القيمة |
| :--- | :--- |
| Complete؟ | ✅ نعم (مع كلف موجب و$h \ge 0$) |
| Optimal؟ | ✅ **نعم إذا كانت $h$ admissible** |

### 5.4 Admissibility — الشرط الذي يُسأل عنه دائماً (ص 15)

$$h \text{ admissible} \iff h(n) \le h^*(n) \quad \forall n$$

أي: $h$ **لا تبالغ أبداً** في تقدير الكلفة الحقيقية $h^*$ إلى أقرب هدف.

| الحالة | الاسم | الأثر |
| :--- | :--- | :--- |
| $h(n) < h^*(n)$ | **underestimate** | ✅ مقبول — A* يبحث أكثر لكنه يبقى أمثَلياً |
| $h(n) = h^*(n)$ | **perfect heuristic** | ✅ أمثل، ويوسّع أقل ما يمكن |
| $h(n) > h^*(n)$ | **overestimate** | ❌ **يُسقط الأمثلية** — A* قد يتجاهل الطريق الأرخص |

**الجملة التي يجب حفظها حرفياً:** **المبالغة (overestimating) أسوأ من التقليل (underestimating).** التقليل يكلّفك **وقتاً**؛ المبالغة تكلّفك **درجة**.

**لماذا؟** لأن A* يوسّع بالـ$f$ الأصغر. لو كذبت $h$ على عقدة ورفعت تقديرها، تتأجّل تلك العقدة — وقد تكون على المسار الأرخص. عندها يُخرج A* هدفاً بكلفة أعلى وهو يقول «وجدت».

### 5.5 Consistency (monotonicity) — الشرط الأقوى

$$h(n) \le c(n, n') + h(n')$$

**Consistency $\Rightarrow$ Admissibility** (لكن ليس العكس). المسافة المستقيمة (straight-line) في الخرائط **consistent** دائماً.

### 5.6 IDA\* — التعميق التكراري بالكلفة

نفس فكرة IDS، لكن الحدّ ليس **العمق** بل **الـ$f$**:

$$\text{حدّ العتبة } f \le t, \quad t \text{ يزيد لأقرب } f \text{ تجاوز العتبة}$$

**الميزة:** ذاكرة خطّية مثل DFS مع ضمان أمثلية A*. **العيب:** يعيد العمل، وهذا مؤلم عند وجود كلف متساوية كثيرة.

## 6. المخطط المشترك — كل الخوارزميات على رسم واحد

هذا هو المخطط الذي ستُتبَع عليه كل خوارزمية أدناه. الاحفظه قبل أي تتبّع.

#### المخطط

| الحافة | الكلفة |
| :--- | :--: |
| S–A | 1 |
| S–B | 10 |
| A–B | 1 |
| A–D | 5 |
| B–C | 2 |
| B–G | 1 |
| C–E | 1 |
| C–G | 4 |
| E–D | 1 |
| D–G | 1 |

| العقدة | A | B | C | D | E | G | S |
| :---: | :--: | :--: | :--: | :--: | :--: | :--: | :--: |
| **h** | 1 | 1 | 2 | 0 | 1 | 0 | 1 |
| **h\*** الحقيقية | 2 | 1 | 3 | 1 | 2 | 0 | 3 |

**لاحظ:** $h(n) \le h^*(n)$ في **كل** عقدة ← الـ$h$ **admissible**. تحقّق بنفسك قبل أي تتبّع — هذه أول خطوة في أي سؤال.

**الاصطلاحات المعلنة** (اكتبها في ورقتك، لأنها تغيّر الأرقام):
- المخطط **غير موجّه** (undirected).
- ترتيب توليد الأبناء **أبجدي**.
- اختبار الهدف عند **الإخراج**.
- عند التعادل في الأولوية ← **أبجدي**.
- بحث بياني: **OPEN + CLOSED**.

## 7. التتبّع الكامل — نفس الرسم، سبع خوارزميات

### 7.1 BFS

| الخطوة | OPEN قبل الإخراج | نُخرج | OPEN بعد الإضافة | CLOSED بعد |
| :--: | :--- | :--: | :--- | :--- |
| 1 | S | **S** | A · B | S |
| 2 | A · B | **A** | B · D | S, A |
| 3 | B · D | **B** | D · C · G | S, A, B |
| 4 | D · C · G | **D** | C · G · E | S, A, B, D |
| 5 | C · G · E | **C** | G · E | S, A, B, D, C |
| 6 | G · E | **G** | E | S, A, B, D, C, G |

**النتيجة:** $S \to B \to G$ — الكلفة **11**.

**اقرأ الدرس:** الهدف ظهر في **خطوة العمق الثانية** ( \to B \to G$)، فأخذه BFS لأن **عدد الحركات** أقل. لكن الكلفة **11**! المسار الأمثل $S \to A \to B \to G$ كلفته **3** وعمقه **3**. BFS **لا ينظر للكلفة** — أبداً.

### 7.2 DFS

| الخطوة | OPEN قبل الإخراج | نُخرج | OPEN بعد الإضافة | CLOSED بعد |
| :--: | :--- | :--: | :--- | :--- |
| 1 | S | **S** | A · B | S |
| 2 | A · B | **B** | A · C · G | S, B |
| 3 | A · C · G | **G** | A · C | S, B, G |

**النتيجة:** $S \to B \to G$ — الكلفة **11**.

**اقرأ الدرس:** DFS نزل على $B$ (لأنه آخر ما دُفع) فوجد الهدف فوراً. **حظّ الترتيب**، مو ذكاء. لو عكسنا ترتيب الأبناء لذهب في عمق آخر تماماً — ولهذا DFS **غير مستقر**: نفس المسألة، ترتيب مختلف، مسار مختلف.

### 7.3 UCS

| الخطوة | OPEN قبل الإخراج (بالـ g) | نُخرج | g | h | f | OPEN بعد الإضافة | CLOSED بعد |
| :--: | :--- | :--: | :--: | :--: | :--: | :--- | :--- |
| 1 | S(0) | **S** | 0 | 1 | 1 | A(1) · B(10) | S |
| 2 | A(1) · B(10) | **A** | 1 | 1 | 2 | B(2) · D(6) | S, A |
| 3 | B(2) · D(6) | **B** | 2 | 1 | 3 | G(3) · C(4) · D(6) | S, A, B |
| 4 | G(3) · C(4) · D(6) | **G** | 3 | 0 | 3 | C(4) · D(6) | S, A, B, G |

**النتيجة:** $S \to A \to B \to G$ — الكلفة **3** ✅.

**الدقيقة المهمة — لحظة التصحيح:** في الخطوة 1 وُلدت $B$ مرتين: مباشرة من $S$ بكلفة **10**، وعبر $A$ بكلفة **2**. UCS **يستبدل** الفتحة القديمة بالأرخص. هذه أهمّ عادة في التتبّع: **كلّما وُلدت عقدة من جديد، قارن $g$ الجديدة بالقديمة**.

### 7.4 Greedy / Best-First

| الخطوة | OPEN قبل الإخراج (بالـ h) | نُخرج | g | h | f | OPEN بعد الإضافة | CLOSED بعد |
| :--: | :--- | :--: | :--: | :--: | :--: | :--- | :--- |
| 1 | S(1) | **S** | 0 | 1 | 1 | A(1) · B(1) | S |
| 2 | A(1) · B(1) | **A** | 1 | 1 | 2 | D(0) · B(1) | S, A |
| 3 | D(0) · B(1) | **D** | 6 | 0 | 6 | G(0) · B(1) · E(1) | S, A, D |
| 4 | G(0) · B(1) · E(1) | **G** | 7 | 0 | 7 | B(1) · E(1) | S, A, D, G |

**النتيجة:** $S \to A \to D \to G$ — الكلفة **7** ❌.

**اقرأ الدرس — أهم درس في الفصل:** الـ$h$ كانت **admissible** تماماً (لا تبالغ في أي عقدة)، ومع ذلك Greedy أعطى **7** بدل **3**. لماذا؟ لأن Greedy يستعمل $h$ **وحدها** ويتجاهل $g$. اختار $D$ لأن $h(D)=0$ — «يبدو قريباً» — رغم أن الوصول إليه كلّف **6**. **الـ$h$ الصادقة لا تكفي؛ تحتاج $g$ معها.**

### 7.5 A\*

| الخطوة | OPEN قبل الإخراج (بالـ f) | نُخرج | g | h | f | OPEN بعد الإضافة | CLOSED بعد |
| :--: | :--- | :--: | :--: | :--: | :--: | :--- | :--- |
| 1 | S(1) | **S** | 0 | 1 | 1 | A(2) · B(11) | S |
| 2 | A(2) · B(11) | **A** | 1 | 1 | 2 | B(3) · D(6) | S, A |
| 3 | B(3) · D(6) | **B** | 2 | 1 | 3 | G(3) · C(6) · D(6) | S, A, B |
| 4 | G(3) · C(6) · D(6) | **G** | 3 | 0 | 3 | C(6) · D(6) | S, A, B, G |

**النتيجة:** $S \to A \to B \to G$ — الكلفة **3** ✅.

**الدقيقة المهمة — لحظة الإنقاذ:** في الخطوة 1 كانت $B$ بـ$f = 10+1 = 11$. في الخطوة 2 وصلناها عبر $A$ بـ$g = 2$، فصار $f = 2+1 = \mathbf{3}$. **A\* حدّث الفتحة ونزل بها من 11 إلى 3** — وهكذا تجاوزت $D(6)$ قبل أن تُستكشف. هذا بالضبط ما فعله UCS، لكن A* **أوقف** البحث مبكراً بفضل $h$.

### 7.6 IDS

| الحد الأقصى للعمق | العقد المزارة بالترتيب | وجد الهدف؟ |
| :--: | :--- | :--: |
| 0 | S | ❌ |
| 1 | $S \to B \to A$ | ❌ |
| 2 | $S \to B \to G$ | ✅ |

**النتيجة:** $S \to B \to G$ — الكلفة **11** ❌.

**اقرأ الدرس:** IDS وجد الهدف عند العمق **2** — نفس فكرة BFS بالضبط. **الذاكرة** تحسّنت، لكن **الأمثلية** لم تتحسّن: العمق ليس كلفة.

### 7.7 IDA\*

**العتبة $f \le 1$:**

| العقدة | g | h | f | القرار |
| :--: | :--: | :--: | :--: | :--: |
| S | 0 | 1 | 1 | توسيع |
| A | 1 | 1 | 2 | قطع |
| B | 10 | 1 | 11 | قطع |

**العتبة $f \le 2$:**

| العقدة | g | h | f | القرار |
| :--: | :--: | :--: | :--: | :--: |
| S | 0 | 1 | 1 | توسيع |
| A | 1 | 1 | 2 | توسيع |
| B | 2 | 1 | 3 | قطع |
| D | 6 | 0 | 6 | قطع |
| B | 10 | 1 | 11 | قطع |

**العتبة $f \le 3$:**

| العقدة | g | h | f | القرار |
| :--: | :--: | :--: | :--: | :--: |
| S | 0 | 1 | 1 | توسيع |
| A | 1 | 1 | 2 | توسيع |
| B | 2 | 1 | 3 | توسيع |
| C | 4 | 2 | 6 | قطع |
| G | 3 | 0 | 3 | توسيع |

**النتيجة:** $S \to A \to B \to G$ — الكلفة **3** ✅.

**اقرأ الدرس:** العتبة **تزيد** لأقل $f$ تجاوزها (1 ← 2 ← 3). وفي كل جولة **يعيد DFS من الجذر** — هذا ثمن الذاكرة الخطّية.

| الخوارزمية | المسار | الكلفة | أمثَلي؟ |

| DFS | $S \to B \to G$ | 11 | ❌ |

| UCS | $S \to A \to B \to G$ | **3** | ✅ |

**ثلاث عائلات من النتائج على رسم واحد:**

2. **7** ← ما يعرف **الاتجاه** لكن يجهل **الكلفة المدفوعة** (Greedy).
3. **3** ← ما يجمع **الاثنين** (UCS · A\* · IDA\*).

## ✎ أسئلة — صياغة المسألة والقالب

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">1</span> **س1.** صِغ مسألة الثمانية (8-puzzle) بالعناصر الخمسة.

**الحل:**

| العنصر | الصياغة |
| :--- | :--- |
| **States** | مواقع القطع الثمانية + الفراغ (9 مواقع) |
| **Initial state** | أي تشكيلة بداية محددة |
| **Goal test** | القطع مرتّبة 1–8 حول المربع |
| **Operators** | حرّك الفراغ يساراً · يميناً · أعلى · أسفل |
| **Path cost** | 1 لكل حركة |

**إضافة مهمة:** عدد الحالات $= 9! / 2 = 181{,}440$ (نصفها قابل للوصول لأن التبديلة الفردية مستحيلة). هذا الرقم يبيّن لماذا BFS **ممكن** هنا — لكن مساحة 10⁴ عقد/ثانية تعني أن BFS يستهلك الذاكرة قبل الوقت.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">2</span> **س2.** ليش نقول إن BFS **complete** لكن **not optimal**؟

**الحل:**

**Complete:** يوسّع مستوى $d$ بالكامل، فإن كان الهدف في العمق $d$ **لا يمكن** أن يفوته — ما دام $b$ منتهياً.

**Not optimal:** لأنه يختار **أقل عدد حركات**، والحركات **مو متساوية الكلفة**. في مخططنا: $S \to B \to G$ حركتان بكلفة 11، و$S \to A \to B \to G$ ثلاث حركات بكلفة 3. BFS يُخرج الأولى.

**الاستثناء الوحيد:** لو كل الكلف متساوية (cost = 1 لكل حركة)، يصبح **عدد الحركات = الكلفة**، وBFS **optimal**. ولهذا يُكتب في الجدول: «optimal **not necessarily least-cost unless all operators have equal cost**» — وهذه العبارة المطلوبة في الامتحان.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">3</span> **س3.** ليش يُفضَّل DFS على BFS عندما تكون الذاكرة القيد؟

**الحل:**

$$\text{BFS}: O(b^{d+1}) \qquad \text{DFS}: O(bm)$$

الفرق **أُسّي مقابل خطّي**. بأرقامك: $b=10$، $d=10$، $m=10$:

|  | BFS | DFS |
| :--- | :--: | :--: |
| العقد بالذاكرة | $10^{11}$ | $10 \times 10 = 100$ |

فرق **بليون** مرّة. لهذا الذاكرة — لا الوقت — هي القيد العملي، وDFS (وIDS الذي يشبهه) يُستعمل رغم أنه **غير complete**.

**الشرط:** إن كانت الشجرة عميقة بلا حدّ، DFS يضيع. لهذا IDS: ذاكرة DFS + ضمانة العمق.

## ✎ أسئلة — التتبّع

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">4</span> **س4.** في مخططنا، ليش وُلدت العقدة $B$ **مرتين** في تتبّع UCS، وما قيمتا $g$؟

**الحل:**

| الطريق | الحساب | $g$ |
| :--- | :--- | :--: |
| مباشرة $S \to B$ | $0 + 10$ | **10** |
| عبر $A$: $S \to A \to B$ | $0 + 1 + 1$ | **2** |

UCS يحتفظ بالأرخص، فيستبدل الفتحة $B(10)$ بـ$B(2)$. ولهذا يظهر في OPEN بعد الخطوة 1: `A(1) · B(10)`، وبعد الخطوة 2: `B(2) · D(6)` — الرقم **نزل**.

**القاعدة العامة:** كلّما وُلدت عقدة من جديد، افحص إن كان المسار الجديد **أرخص**. إن كان أرخص ← استبدله. هذه العادة تمنع 80% من أخطاء التتبّع.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">5</span> **س5.** احسب $f$ لكل عقدة في الخطوة الأولى من A\*، وبيّن أي عقدة تُوسَّع أولاً.

**الحل:**

| العقدة | $g$ | $h$ | $f = g+h$ |
| :--: | :--: | :--: | :--: |
| $A$ | 1 | 1 | **2** |
| $B$ | 10 | 1 | **11** |

$$f(A) = 1 + 1 = 2 < f(B) = 10 + 1 = 11$$

**تُوسَّع $A$ أولاً.** وهي — لحسن الحظ — على المسار الأمثل.

**لو كان ترتيبنا معاكساً** (لو دخلت $B$ بـ$f$ أقل)، لكان A* نزل نحو $B$ ثم اكتشف أن طريقها غالٍ ورجع. ولهذا يجب إعادة الحساب عند كل تحديث.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">6</span> **س6.** Greedy أعطى 7 وA\* أعطى 3 على نفس المخطط بنفس $h$. فسّر الفرق في سطرين.

**الحل:**

Greedy رتّب بالـ$h$ **وحدها**، فاختار $D$ لأن $h(D)=0$ — «يبدو ملاصقاً للهدف» — رغم أن الوصول إلى $D$ كلّف $g=6$. ثم $D \to G$ كلّف 1، فصار المجموع **7**.

A\* رتّب بالـ$f = g+h$، فظهر $f(D) = 6+0 = 6$ — **أغلى** من $f(G \text{ عبر } B) = 3+0 = 3$. فأخذ الطريق الأرخص **3**.

**الخلاصة:** $h$ الصادقة (admissible) **ضرورية** للأمثلية لكنها **غير كافية** — لازم تُجمع مع $g$.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">7</span> **س7.** $h$ في مخططنا admissible. برهن ذلك لعقدتين، وبيّن ماذا يحدث لو رفعنا $h(D)$ إلى 4.

**الحل:**

**البرهان لـ$C$:** الطريق الأرخص من $C$ إلى $G$ هو $C \to E \to D \to G = 1+1+1 = 3$. و$h(C) = 2 \le 3$ ✅.

**البرهان لـ$A$:** الأرخص $A \to B \to G = 1+1 = 2$. و$h(A) = 1 \le 2$ ✅.

**لو صارت $h(D) = 4$:** الكلفة الحقيقية $h^*(D) = 1$، فصار $4 > 1$ ← **overestimate** ← **غير admissible**.

**الأثر العددي:** $f(D) = g(D) + h(D) = 6 + 4 = 10$. و$f(G\text{ via }B) = 3$. فـA* يوسّع $G$ أولاً — **وينجو هنا بالحظ**. لكن في مخططات أخرى قد يُخرج هدفاً بكلفة أعلى ويقول «انتهيت». **ولهذا المبالغة خطر:** لا تُسقط الأمثلية دائماً، لكنها **لا تضمنها**.

## ✎ أسئلة — الأمثلية والتعقيد

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">8</span> **س8.** عرّف admissibility وconsistency، وبيّن العلاقة بينهما.

**الحل:**

$$h \text{ admissible} \iff h(n) \le h^*(n) \ \forall n$$

$$h \text{ consistent} \iff h(n) \le c(n,n') + h(n') \ \forall (n,n')$$

| الشرط | يقارن | ماذا يضمن |
| :--- | :--- | :--- |
| **Admissibility** | $h$ بـ**الكلفة الحقيقية للهدف** | A\* **optimal** |
| **Consistency** | $h$ **بعقدتين متجاورتين** | A\* **optimal** بلا إعادة فتح، وترتيب $f$ **لا يتراجع** |

**العلاقة:** Consistency $\Rightarrow$ Admissibility، **لكن ليس** العكس.

**الفائدة العملية:** مع heuristic **consistent**، لا تحتاج إعادة فتح عقدة مغلقة — كل عقدة تُوسَّع مرة واحدة. ولهذا تُفضَّل consistency عملياً.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">9</span> **س9.** تفسير IDS: شكد مرة تُولَّد العقدة الجذرية عند $d=3$ و$b=2$؟

**الحل:**

الجذر يُزار مرة في كل جولة. عدد الجولات $= d + 1 = 4$ (الحدود 0، 1، 2، 3).

$$\text{مرات الجذر} = d + 1 = 4$$

**وللعقدة عند العمق 1:** تُزار في الجولات التي حدّها $\ge 1$ ← 3 مرات.

**التعميم:** العقدة عند العمق $k$ تُزار $d + 1 - k$ مرات.

**ليش هذا مقبول؟** مجموع العمل:

$$N(IDS) = (d+1)b^0 + d\,b^1 + (d-1)b^2 + \cdots + 1 \cdot b^d$$

وهذا **داخل ثابت** من $b^d$ — أي أن التكرار **لا يغيّر التعقيد**. المستويات العليا (المكرّرة أكثر) هي الأرخص، فلا يهمّ.

---

<span style="display:inline-block;min-width:1.5em;height:1.5em;line-height:1.5em;text-align:center;border-radius:50%;background:#dc2626;color:#ffffff;font-weight:700;font-size:0.85em;">10</span> **س10.** ليش BFS يُكتب $O(b^{d+1})$ وليس $O(b^d)$؟

**الحل:**

لأن الهدف يُفحص **عند الإخراج**، ولأن كل مستوى يُولَّد **كاملاً** قبل إخراج أي عقدة من المستوى التالي:

$$\underbrace{1}_{d=0} + b + b^2 + \cdots + b^d + \underbrace{(b^{d+1} - b)}_{\text{أبناء العقد في } d} = O(b^{d+1})$$

الحدّ الأخير هو المفتاح: قبل أن تُخرِج الهدف في المستوى $d$، يكون قد **ولّد** أبناء كل عقد المستوى $d$ — وهي الأغلبية الساحقة.

**ولو فحصنا الهدف عند التوليد** (وهو اختيار آخر مشروع)، لصار $O(b^d)$. **ولهذا يجب أن تعلن اصطلاحك** قبل التتبّع.

## 9. ورقة الصيغ

| العنصر | الصيغة |
| :--- | :--- |
| كلفة المسار | $g(n) = \sum c$ على المسار من الجذر إلى $n$ |
