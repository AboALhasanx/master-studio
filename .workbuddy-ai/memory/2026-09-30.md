# 2026-09-30 — Telegram interactive layer + gateway memory boundary (D14/D15/D16)

> Engineering track only. No academic vault state touched.

## Trigger

Student asked for three things in one message:
1. Telegram must live **inside** Master Studio with **correct declared boundaries** and a
   **partially-separated memory** — explicitly **not** total isolation ("كذاكرة يعني").
2. **Feature 1:** anyone can **mention the bot in a reply** → the bot **reads that message**
   and **replies** to it according to its content and capability.
3. **Feature 2:** every **administrative group command** must require **his (the admin's) approval**.

## Diagnosis before code (the two destiny-level gates)

- Request 1 (boundaries/memory): architecturally sound, no conflict. Real defect found —
  the gateway was writing `00_STUDIO_HUB/MEMORY.md` **directly** with no declared owner and no
  contract. Fixed by contract, not by a new subsystem.
- Request 2 (mention/reply): **literally breaks ADR D2** (`No getUpdates loop`).

Presented two patterns and let him choose (depth/scope = his call, per standing rule):
- **A — permanent service** (webhook or daemon): always listening, needs hosting, always at risk.
- **B — on-demand bridge** (one-shot listening session): no hosting, no standing attack surface.

**He chose B + a gateway-owned memory folder.** Nothing was written before that choice.

## The three new ADRs

| # | Decision | Essence |
|:--|:--|:--|
| **D14** | Gateway memory boundary | Folder `00_STUDIO_HUB/telegram/` with a **declared contract**: the gateway writes its own folder freely, reads project memory freely, and **never writes `MEMORY.md` directly** — the agent is the mediator. |
| **D15** | Interactive layer | **One bounded listening session** (`--for` / `--max`), **not** a permanent loop. Mandatory allowlist (fail-closed), `update_id` persisted so nothing repeats or is lost. |
| **D16** | Admin approval gate | Every admin verb (`/delete`, `/pin`, …) becomes a **pending request** for the owner — **never auto-executed**, even when the actor is the student himself. Sits on top of the owner allowlist and the `--confirm` gate: three layers, default deny. |

## What was actually built (all tested, nothing live)

### D14 — gateway memory (`90_Shared_Toolbox/telegram/telegram_memory.py`, 170 lines)
```
00_STUDIO_HUB/telegram/
├── README.md              ← the explicit contract
├── TELEGRAM_MEMORY.md     ← gateway preferences/decisions
├── STATE.md               ← state (machine-readable JSON block)
├── log/2026-09-30.md      ← append-only log
└── pending_approval.json  ← (gitignored — runtime state)
```
API: `record_post` / `append_log` / `read_state` / `set_state` / `read_prefs` / `last_state`.
- **Atomic writes** (temp + `os.replace`) — never a torn file on interruption.
- **Best-effort** — a memory failure can never break a real post.

### D15 — interactive layer (`90_Shared_Toolbox/telegram/interactive.py`, 423 lines)
`run_session()` + `extract_mentions()` + `build_reply()` + `SessionLimits` + `Mention` + `ListenResult`.
- **Fail-closed on every axis:**
  - no `TELEGRAM_CHAT_ALLOWLIST` → refuse **before** any network call (exit 3).
  - no `--live` → refuse (exit 5).
  - bad window (`--for 0`) → refuse (exit 2).
  - mention from a foreign chat → **refused + audited**, no `sendMessage`.
- Intent is parsed from the text after stripping the mention; `/help` and the help word both
  resolve to `help` (fixed via `Mention.stripped` + `wants_help`).

### D16 — approval gate
- Any verb in `ADMIN_VERBS = {delete, pin, unpin, unpin-all, close, reopen, topic-delete, ban}`
  → recorded in `pending_approval.json` (actor/chat/command/args/ts) and answered with
  "awaiting admin approval". **Never auto-executed.**

### CLI
- New `interactive` subcommand (global `--live` must precede it).
- Flags: `--for` / `--max` / `--bot-username` / `--subject`.
- **`interactive` is deliberately NOT in `schema.VERBS`** → it can never ride the publish path.
  A test pins this (`test_interactive_is_not_a_schema_verb`).

## Lessons recorded

1. **Global flags before the subcommand:** `--json`, `--live`, `--dry-run` must precede the
   subcommand or argparse rejects them.
2. **`audit` takes `(verb, result)` positionally** — not a keyword. Two tests failed assuming `result=`.
3. **`load_dotenv` does not override `os.environ`** — a shell override wins, which is exactly what
   made the "no allowlist" test possible.
4. **Naive source assertion** (`assert "MEMORY.md" not in source`) failed on a docstring mention —
   replaced with an **AST-based string-literal check** (asserts the module never *references* the
   path as a literal, ignoring prose).
5. `.env` malformed-line trap: `printf "\T…"` merged two lines; fixed with a Python rewrite.
