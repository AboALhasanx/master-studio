**Bug (worth remembering — it is a recurring class in this vault):**
The HTML builder `90_Shared_Toolbox/tools/build_w02_fuzzy_booklet.py` embeds LaTeX inside ordinary (non-raw) Python strings. Single-backslash commands get eaten by Python's escape parser:
- `\tilde` → TAB + `ilde` → rendered as `ilde{A}` instead of `Ã`
- `\varphi` → `\v` consumed → rendered as `arphi` instead of `φ`

Detection recipe (run against the *generated HTML*, not the builder):
```python
s = open(html, encoding='utf-8').read()
print(s.count('\t'))                                   # must be 0
print(len(re.findall(r'\\[vtnrabf](?![a-zA-Z])', s)))  # must be 0
```
**Prevention:** when embedding LaTeX in Python string literals, double every backslash (`\\tilde`) or use a raw string (`r"""..."""`). Never assume the generated HTML is clean just because the builder "looks right".

**Repair:** `fix_tex_escapes.py` doubled the backslashes; then the HTML was regenerated and the PDF re-rendered. Do not patch the generated HTML by hand — always fix the builder and rebuild.

## Scientific correction — Cartesian product vs. fuzzy-set graph

**Lesson worth keeping (an agent-authoring failure mode, not a maths one):** when I add an explanatory *bridge* between two sourced facts, the bridge is **my own claim** and carries the full anti-fabrication burden. I wrote that the Cartesian product "produces" the pairs `(x, μ(x))` — a stronger claim than the source supports, and stronger than is true. Source page 33 defines the product and gives the `{a,b} × {1,2}` example only; it never mentions fuzzy sets. **Mark editorial bridges as bridges.**

**The correct statement (use this wording again):**
- `Ã = {(x, μ_Ã(x)) | x ∈ X}` is the **graph of the membership function**.
- The graph is a **subset of** `X × [0,1]`; the product supplies the **ambient space** of possible (element, grade) pairs — necessary, not sufficient.
- **`μ_Ã` selects** the pairs: exactly one grade per element.
- A fuzzy set on `X` is a **function** `X → [0,1]`, so its graph is *functional*, not an arbitrary subset of the product.
- The product alone does **not** build the fuzzy set.

**Fix applied in two places:** the booklet builder's Cartesian page (table + Precision trap + source note; HTML/PDF regenerated and page 14 visually confirmed) and quiz Q12 (new stem asking for the *precise role*, `bloom_level` → Analyze, `concept_id` → `cartesian_product_ambient_space`, rewritten explanation).

**Technique note:** to change one question's key without churning the others, do **not** re-run `quiz_balancer.py` (it re-permutes every question). Re-permute only the edited question's `options` / `options_ar` / `options_en` with one shared index map and set its `answer` to the letter that restores the 3/3/3/3 split. Then `--strict --check` to prove it.
