### Environment gotcha — the safe-delete guard and locked files (cost ~10 minutes)
The vault's safe-delete guard routes `rm` / `os.unlink` / `shutil.move` through the Windows Recycle Bin and is **fail-closed**. When a file is **open in a PDF viewer**, the trash operation aborts with
`[safe-delete][SAFE_DELETE_FAIL_CLOSED] … trash-failed … "Some operations were aborted"`,
and the real cause is only visible in the Python traceback: `PermissionError: [WinError 32] The process cannot access the file because it is being used by another process`.
- `rm -rf` on such a file **hangs indefinitely** (it auto-backgrounds and never completes) — do not wait on it.
- **Detection:** `shutil.move` each file in a `try/except PermissionError` and report the locked ones instead of retrying.
