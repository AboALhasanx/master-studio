# Master Studio Tool Radar

A holding area for newly discovered GitHub projects and tools that may improve Master Studio. Candidates stay here until they pass a small, source-representative local evaluation.

## Workflow

1. Record the project, discovery date, source URL, and the Master Studio task it may help.
2. Check the license, runtime and hardware requirements, offline behavior, data handling, and how actively maintained the project is.
3. Compare it with the current Master Studio workflow on a small, representative sample. Keep originals untouched and put outputs in a dated folder under `00_STUDIO_HUB/scratch/tool_radar/`.
4. Log measurable results and limitations here. Do not replace a canonical tool or workflow until the comparison supports that decision.
5. Move candidates to `Adopted`, `Keep for later`, or `Rejected` with a short reason.

## Evaluation checklist

- What task does it improve, and where does that task occur in Master Studio?
- Does it run locally/offline? What data leaves the computer, if any?
- What are the model, hardware, installation, and maintenance requirements?
- Does its license cover both source code and model weights? Record uncertainty rather than assuming.
- On the same inputs, how does it compare for correctness, layout, tables, equations, Arabic, page order, figures, and runtime?
- Did a human inspect every error-sensitive result against the original source?
