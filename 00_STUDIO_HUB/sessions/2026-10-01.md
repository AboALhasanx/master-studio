## 1. الهدف: تسجيل الدخول فعلياً (الخطوة الوحيدة الناقصة)

الحساب الاحتياطي `+9647***…***51` — كود التحقق `39736` قُبل من الجهاز، ثم أوقفه **الخطّافان (2FA)**:

```
SessionPasswordNeededError: Two-steps verification is enabled and a password is required
```

### المصيدة الأولى — `sign_in` في Telethon ليست دالة بل سلسلة `if/elif`

```python
if phone and not code and not password:  → send_code_request(phone)   # يرسل كوداً جديداً!
elif code:                               → verifies the CODE          # يتجاهل كلمة المرور!
elif password:                           → CheckPassword
```

إذن `sign_in(phone, code, password=...)` يذهب إلى **فرع الكود**، يتجاهل الكلمة تماماً، ويعيد **الخطأ نفسه للأبد** — ولو أن التنفيذ مرّ من المسار المنطقي "سلّم الاثنين معاً" لصار الملفق غير قابل للاختراق نظرياً وعملياً.

**الحل:** الفرعان مُفصولان في `TelethonGateway.sign_in` — كلمة المرور تُسلَّم **وحدها** (`code=None`). وسلّمته **بدون `--code`** بالضبط كما يقتضي `elif`.

### التحقق

```json
{ "status": "ok", "verb": "login", "result": { "authorized": true, "user_id": 8404964768 } }
```

- **النقل المُسلَّم (`login_state.json`) نجى** من تحدّي الـ2FA ولم يُمحَ سوى بعد النجاح → أخطئة كلمة المرور لا تكلّفك كوداً جديداً.
- **كلمة المرور لم تُسكَب إلى قرص أبداً:** بحث في سجلّات OpenCE + المؤقّت + الريبو = صفر · `git log -S <password>` عبر كل الـ commits = صفر · ليست في `.env` — وجودها الوحيد نصّ المحادثة.

## 4. الرجل الثالث لـ AC2 — الـ monitoring

`#22` يشترط: *flood-control policy, **monitoring**, and kill switch* — والاثنان الأولان كانا موجودين، والثالث **لم يكن**.

- كل محاولة (ناجحة أو مرفوضة) تكتب سطر واحد في جدول `audit` باسمية **`human:<verb>`** — فلا تُخلط أفعال شخص أبداً مع أفعال البوت (`read`/`say` من `schema.VERBS`، و`human:read`/`human:say` لا).
- المفردات نفسها المستعملة في `executor`: `ok` · `sent` · `denied` · `rate_limited` · `error` · `refused`.
- `detail` يحمل السبب، ولـ`say` **النصّ المنطوق فعلاً** مع `message_id` — الحقل الوحيد الذي لا يجوز أن يضيع.
- الكتابة **بلا `try/except`** عمداً، تماماً ككل `store.audit(...)` في `executor`: سجلّ يفشل يجب أن يظهر بصوت عالٍ، لا أن يمرّ عملٌ بلا مراقبة — وهذا بالضبط ما يُبطل رجل AC2.

**وأصلحت اختباراً يكذب على نفسه:** `test_ac2_controls_are_documented` كان وصفه يقول إنه يفحص الـ monitoring **ولا يفحصه**. صار يشترط وجود قسم `Monitoring.` و`human:<verb>`، فلا ينفصل الادّعاء عن التحقيق ثانية.

### دروس مسجّلة

1. **`sign_in` في Telethon دالة بسلسلة `if/elif` لا بفروع مستقلة** — "سلّم كل ما تعرفه" يذهب إلى الفرع الأول فقط ويتجاهل الباقي بصمت. الاختبار الذي يمرّ بـ`**kw` لا يكشف ذلك أبداً؛ يكشفه الإدخال الحقيقي وحده.

3. **الاختبار الأخضر محلياً هو الأسوأ أنواع الأختبار** — لأن بيئتك تُوفّق ما لا تُوفّقه CI. التحقق الصحيح: *أشغّل الاختبار في ظروفه لا في ظروفك* (حذفت `.env` فعلياً).
4. **أداة المراقبة تكشف عيوب أداة أخرى:** بصمة سجلّ التدقيق قبل/بعد السلسلة هي ما كشف التلوث — ولا شيء آخر كان سيفعل.
5. **لا يُمحى سجلّ تدقيق:** الصفوف الكاذبة بقيت موثّقة لا ممسوحة، لأن المحو نفسه فعلٌ غير قابل للتدقيق.
