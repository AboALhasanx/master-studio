### 2.2 Issue #18 — MCQ publishing bridge, Phase A
**Goal (from the issue's own acceptance criteria):**
1. One command publishes a **working exam link** to the correct topic.
2. The **quiz JSON format stays shared** — no second engine.
3. Phase B (native `sendPoll` quiz) stays **documented as deferred**.

**Design:** a new `quiz` verb that composes a deep link to the existing Flask route
(`/quiz/<subject>/<quiz>?mode=…`) and publishes it as a message with URL buttons into
the registry-resolved subject topic. This is *pure composition* — it adds no quiz
engine, reads no answers, and honours the one-directional scope (ADR D2/D4).

**Why this shape:** the dashboard already owns the quiz engine, the JSON schema
(`quiz_balancer.normalize_quiz_schema`), BKT and `/api/quiz/submit`. The gateway's job
is to publish the door, not to rebuild the room.
